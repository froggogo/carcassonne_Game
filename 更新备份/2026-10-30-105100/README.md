# 卡卡颂 · 山河之间（网页版）

这是可玩的首版网页游戏，包含离线 1 对电脑、同设备 2–6 人轮流游戏，以及不同设备访问同一服务器的联网房间。

## 立即开始

Windows 双击 `启动游戏.cmd`，保留服务器窗口，再在浏览器打开：

<http://localhost:8787>

也可以在本文件夹执行：

```text
npm start
```

需要 Node.js 18 或更新版本。服务器仅使用 Node 内置库，不需要执行 npm install。

单独打开 `public/index.html` 可以离线玩人机和本地多人；不同浏览器对本地文件自动保存的支持有差异，可使用“导出存档 / 导入存档”。

## 不同设备联网

1. 在一台电脑运行服务器，其他玩家的手机或电脑与它处于可互相访问的网络。
2. 服务器窗口会显示该电脑的局域网地址，例如 `http://192.168.x.x:8787`。所有玩家在各自设备打开这一地址；其他设备不能用自己的 localhost 访问你的电脑。
3. 房主选扩展，点“联网多人 → 创建联机房间”；朋友输入房间码，或打开邀请链接。
4. 全员准备后，房主点“开始对局”。服务器校验落子、米宝与计分，通过 SSE 同步每名玩家。
5. 刷新网页会用同一浏览器当前标签页保存的身份重连。服务器保持运行时，房间留在内存；关闭服务器后，当前房间不会跨进程保存。

跨互联网对战需要把本服务器部署到所有玩家可访问的主机，或使用可访问的网络入口。项目已具备房间服务器，尚未发布公共互联网网址。反向代理需支持长连接 SSE，避免缓冲 `/api/events`。

如 Windows 防火墙询问网络访问，在你需要联网的网络上允许此 Node 服务。可用 `PORT` 环境变量修改默认 8787 端口。

## 游戏操作

- 鼠标移动到地图空格，版图平滑吸附；绿色允许放置，红色标出冲突边并解释原因。点击确认落子。
- R / Q 或左右旋转按钮改变方向；H / ✦ 选择合法位置。
- 落子后选普通米宝或特殊棋子，点击地图圆点或右侧地形按钮派遣；随后结束回合。
- 新放置的米宝在结束回合前处于“待确认”状态。点击“撤销米宝并重选”、再次点地图上的该米宝，或按 Ctrl+Z，可以恢复放置前的状态并重新选择棋子和地形；已放下的版图保留。随米宝的建筑师、猪以及该米宝之后的附属选择也会一起恢复。
- 点击“确认米宝 · 结束回合”后立即锁定，不能撤销。羊群抽取、守望者替换补偿及岗哨守军计分在确认时执行，避免预览阶段提前揭示或计分；联网端同样验证撤销权限与回合状态。
- 提前收回修道院长：在自己的回合放好版图、尚未放新米宝时，派遣区域顶部会显示金色收回按钮与预计得分。也可直接点击地图上金色高亮的自己的院长。点击只预选收回，再点院长或“取消收回”可取消；点“确认收回院长 · 结束回合”后才计分并收回，确认后锁定。普通米宝僧侣不能这样提前收回。
- 建筑师、猪和防御守军可随符合角色的米宝一起放置。大米宝、修道院长、牧羊人、市长、信使等有专门的放置限制。
- 滚轮缩放、拖动平移，⌖ 适配整张地图。手机使用拖动及屏幕按钮操作。
- 人机和本地对局自动保存，也可导出 / 导入 JSON 存档。
- 游戏内“?”可阅读详细基础与扩展规则。完整中文打印规则在 `public/规则总览.pdf`。

## 本版包含

基础游戏的连通地形、合法拼接、米宝占领、多数、并列完整得分、道路 / 城市 / 修道院计分及农夫终局计分。

十二个可选模块：河流、修道院长、旅馆与大教堂、商人与建筑师、巨龙与仙女、高塔与盗贼、信使与市长、比武与纹章、围城与防御、城堡与桥梁、羊群与牧羊人、马戏团与艺人。

版图美术由同一 Canvas 系统绘制，城市、城墙、房屋、教堂、河流、道路、草地、花园、旅馆、塔、藏宝地、马戏场和杂技场均在卡片内展示；使用高清 Canvas、卡片轻落动画、吸附预览、米宝绘制与得分浮字。

2026-10-29 更新：修正转角城市在草地边的城市色块，开放城市边不画城墙；教堂、旅馆、盾徽与货物符号增强辨识度，版图默认以 440 像素绘制。圆形关闭按钮使用几何居中的 X，规则与结果弹窗均可正确关闭。

## 网页适配范围

此版本使用 2025 重制版的主要机制，并使用原创牌型配比和美术；不是官方数字版，也没有复刻全部实物版图的精确图案与数量。

- 河流使用单河源 / 单河湖起始流程。大型比武图与堡垒图的控制空间用独立面板表示，未复刻双河源、双河湖与大型起始版图的六格地形。
- 比武按网页牌堆数量分阶段。玩家自行提名及选择纹章，系统默认在已提名代表中选择当前最高值参赛；分堆不使用全部官方组合数量表。
- 巨龙两次直线移动与合法目标朝向已实现，默认系统定向，自己的米宝行动阶段可调整合法朝向。
- 市长包围后默认转换一枚合法对手普通骑士；稻草人默认躺倒；信使默认进入一个合法相接的未完成地形。实体规则中这些动作的自由选择范围更大。
- 市政厅可在候选版图已显示后替换放置，候选图会保留给后续回合；已处理的抽图事件不会再次触发。这与实体版抽图前选择市政厅的时机不同。
- 仙女、米宝回收、猪、羊群、马戏团、建筑和防御岗哨使用各自事件顺序；复杂扩展交互仍以游戏内适配说明为准。规则手册提供实体版规则，便于识别差异。
- AI 是基于地形完成、占领和库存的启发式对手，可完成整局，没有声称达到赛事水平。

## 验证

```text
npm test
node tests/network.cjs
```

已通过核心规则断言、基础与每个单扩展整局、全扩展 2/4/6 人整局、两名真实 HTTP/SSE 客户端的同步 / 准备 / 越权拒绝 / 重连测试。另有 DOM 交互检查及实际 Canvas 美术渲染检查。

Windows 隔离浏览器验收启动失败：`CreateWindowStationW: 拒绝访问 (os error 5)`。因此没有把 Canvas 预览声称为实际浏览器截图，手机与浏览器布局还未经过真实浏览器自动验收。详见 `验证记录.md`。

## 文件

- `public/index.html`、`style.css`、`app.js`：界面与交互。
- `public/engine.js`：浏览器与服务器共用的规则逻辑。
- `public/art.js`：原创版图与米宝绘制。
- `public/rules.js`：中文规则手册。
- `server.cjs`：HTTP / SSE 房间服务器，校验全部联网操作。
- `tests/`：可直接运行的规则与联网测试。

官方规则来源：<https://cundco.de/en/rules/cc-basegame-expansions>。中文名称为规则指南的便捷译名。
